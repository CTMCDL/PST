# Propensity Straight-Through Gradients for Discrete Stochastic Systems

TensorFlow implementations and experiments accompanying:

J. M. G. Vilar and L. Saiz, *Propensity Straight-Through Gradients for Discrete Stochastic Systems*, arXiv:2608.25631 (2026). [doi:10.48550/arXiv.2608.25631](https://doi.org/10.48550/arXiv.2608.25631)

Propensity straight-through (PST) gradients combine discrete stochastic forward simulations with differentiation through normalized reaction propensities. The notebooks compare PST with Gumbel–Softmax straight-through (GS-ST) estimators in chemical-reaction, ion-channel, genetic-oscillator, and repressilator models, and apply PST to a stochastic gene-regulatory classifier for MNIST.

## Quick start

The environment targets **Linux x86_64 with NVIDIA GPUs** and uses Python 3.11.15 and TensorFlow 2.20.0. Install an NVIDIA host driver before creating the environment. From the repository root:

```bash
conda env create -f environment.yml
conda activate pst
python -m pip check
python -m ipykernel install --user --name pst --display-name "PST (Python 3.11)"
python -m jupyter lab
```

Select the `PST (Python 3.11)` kernel and run each notebook from its containing directory. The default settings implement the full research protocols and can require substantial runtime and GPU memory. See [Software environment](docs/ENVIRONMENT.md) for dependencies and GPU verification, and [Running the notebooks](docs/RUNNING.md) for execution settings and result reuse.

To run the experiments across four GPUs:

```bash
conda activate pst
bash run_all_4gpus.sh
```

The launcher runs four workload queues concurrently, followed by the timing benchmarks. It writes logs beneath `logs/` and updates notebook outputs in place. See [Running on four GPUs](docs/RUNNING.md#running-on-four-gpus) for the schedule and rerun options.

## Data and results

The repository includes:

- The processed patch-clamp recording `HEK293_Cell01_40mV_100s_raw_DET_IDEl.xlsx` in `IonChannel/`, `IonChannelMR/`, and `Timing/`.
- The repressilator task parameters `params__truth_init.npy` in `RepressilatorPST/` and `RepressilatorBurgerLoss/`.
- The GS-ST oscillator baseline `Oscillator/oscillator_results_gsst_vilar_saiz.pkl`.

MNIST is downloaded through `tf.keras.datasets.mnist` on first use. Dataset attribution and related methods are described in [Data sources](DATA_SOURCES.md).

Run `Oscillator/Oscillator-run.ipynb` before the oscillator analysis to generate `experiment_results_pst_3000_stateless_categorical.pkl`. The analysis requires this PST result and the included GS-ST baseline; the GS-ST training workflow is not included.

Training histories, weights, checkpoints, reference trajectories, figures, and timing measurements are generated by the notebooks. Compatible results can be reused as described in the [run guide](docs/RUNNING.md). Saved notebook outputs can be viewed without execution.

## Hardware and timing

The reference system uses four NVIDIA RTX 6000 Ada Generation GPUs, each with 49,140 MiB of memory, on Ubuntu 22.04.5 with NVIDIA driver 580.178.04.

The coherent timing benchmark compares PST and GS-ST within each device profile. The CPU profile uses one eighth of the GPU profile's trajectory count, so compare method timings within a profile rather than absolute GPU and CPU elapsed times. See [Timing profiles](docs/RUNNING.md#timing-profiles) for workload sizes and measurement settings.
